## 3. 交互规则（谁按什么发生什么）

| 操作 | 位置 | 效果 |
|---|---|---|
| **长按 1 秒** | 腕端按钮 SW3 | 模拟跌倒（联调专用）：腰端直接触发报警流程 |
| 短按 | 腕端按钮 | 预留交互（OLED 翻页 TODO，现无动作） |
| **按压一下** | 腰端编码器 | **取消报警**并复位系统（仅报警态有效） |

**报警状态机**（触发后自动流转，10s / 推送两个节点）：

```
触发(真摔或长按模拟)
  → [0~10s 取消窗] 蜂鸣器急促哔哔(0.3响/0.2停) —— 按编码器 → 全停+复位
  → [10s 到] 自动连WiFi推送微信 → 蜂鸣器转长鸣(0.8响/0.2停) —— 按编码器 → 停+复位
  → 复位后需站直5s重新采基线（串口 detector armed）
```

**腕端 LED 闪法**：每2s短闪=一切正常；每秒闪=链路故障(腰端没开/信道不对)；
快速闪=MPU 离线。

**使用纪律（不是 bug，摘戴会伪触发）**：先佩戴→再上电；关机→再摘下；
MPU 板面平贴腰前。

## 4. 串口日志速查（调参看什么）

- `[STAT] rx=N lost=N lastAge=Nms`：链路健康，lost 涨=丢包
- `[DETC] decision proba=0.47 peak=78.5 tilt=1deg gyr=500 wrist=11.2/cov98% (3501ms)`：
  **核心行**。proba≥0.4 判跌倒报警；wrist/cov=腕端数据健康度
- `cnn p=0.xx`：CNN 影子记录（**不参与判决**，攒对照数据用，勿据此调参）
- `detector armed`：基线完成，开始判定

## 5. 调参指南（唯一需要动的文件：`waist_firmware/config.h`）

| 参数 | 现值 | 方向 | 效果 |
|---|---|---|---|
| `FD_TRIGGER_SVM` | 30 m/s² | ↓更易触发 | 冲击门限（≈3.1g） |
| `FD_TRIGGER_GYR` | 200 °/s | ↓更易触发 | 旋转门限（与SVM满足其一） |
| `FD_RF_THRESHOLD` | 0.40 | ↓更灵敏、误报升 | **判决门限，主调项**（0.3/0.4/0.5 档见算法交接文档 §2.2） |
| `FD_BASELINE_MS` | 5000 | 一般不动 | 开机站姿基线时长 |
| `FD_COLLECT_MS` | 3500 | 一般不动 | 触发后确认窗 |
| `ALARM_CANCEL_WINDOW_MS` | 10000 | 不建议<6000 | 取消窗 |

**调参方法**：改宏 → 烧腰端 → 按下表协议做动作 → 存档所有 decision 行：

- 协议 A（阴性，要求零报警）：走30s / 快坐×3 / 跳×3 / 弯腰×3 / 下蹲×3
- 协议 B（阳性，要求≥7/9 报警）：垫上侧摔/前扑/后倒各×3，每轮取消后站直5s

误报多 → `FD_RF_THRESHOLD` 上调；漏检多 → 下调 SVM/阈值。改完记录在
`test/logs/`（文件名建议 `param_<日期>_<阈值>.txt`）。

## 6. 外形设计者：改 GPIO 位置的规则

- **腰端随便挪**：杜邦线换到别的 GPIO + 改 `waist_firmware/config.h` 对应宏
  （`PIN_I2C_SDA/SCL/PIN_BUZZER/PIN_BTN_CANCEL`）→ 重烧即生效。
  唯一注意：I2C 两根建议用默认 I2C 脚（8/9），其他脚需软件 Wire 兼容。
- **腕端不能挪**：引脚由 PCB 走线焊死，挪=飞线。需要新传感器/外设时
  用 §2.1 的空闲扩展脚（D0/D3/D7/D8），固件里加宏即可。
- 外壳开孔参考 `腕端PCB交接文档_v1.md` §8（USB-C/OLED窗/SW3/SW2/表带通道）。
  腰端建议腰包方案（蜂鸣器出声、编码器可按、USB 可插）。

## 7. 已知事项与坑（2026-09-14 快照）

1. **OLED 模块已损坏**（PCB 首插疑似错位烧毁），已购新待换；
   无屏不影响任何功能，`OLED init FAIL` 日志为预期
2. **腕端 SW2 电源开关虚焊失效**，已用 P4 焊盘锡桥旁路：
   插电池=开机，拔电池=关机；充电照常（USB 插线）
3. **腰端供电**：桌面调试 Micro USB 即可；**脱离电脑演示必须 ≥6.65V**
   （PD 诱骗线/9V 适配器/2S 电池），5V 充电宝带不动 WiFi
4. **热点信道约束**：手机热点须 2.4G 且实际信道=6（=ESPNOW_CHANNEL）；
   失配串口有 `!!` 告警。换热点先看 `WiFi connected ... ch=X`
5. 推送期间 ESP-NOW 丢包短暂暴涨属正常（WiFi 借射频），推完自恢复
6. `secrets.h` 不入库：新环境复制 `secrets.h.example` 填 WiFi/WxPusher
