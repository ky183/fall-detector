# 踩坑记录：MPU 模块实为 MPU6500，更换裸寄存器驱动

> 日期：2026-09-06 · 记录人：组长 · 影响范围：腕端/腰端传感器层

## 现象

- 腕端固件持续打印 `[SENS] MPU offline, retrying...`，SVM 显示 0
- I2C 扫描器能扫到 0x68（器件"在线"）
- Adafruit_MPU6050 库的 `begin()` 始终失败

## 排查过程（供复用）

1. I2C 扫描器确认器件地址在线 → 排除接线问题
2. 换第二个模块、换杜邦线、量上拉电压（SDA 对 GND ≈3.3V）→ 排除硬件损坏
3. 加诊断日志直接读 WHO_AM_I 寄存器（0x75）→ **读出 0x70**
4. 结论：模块实际是 **MPU6500**（WHO_AM_I=0x70），而非 MPU6050（0x68）
5. Adafruit_MPU6050 库严格校验芯片 ID=0x68，故拒绝初始化——这就是
   "扫描器通、固件不通"的根因

期间还发现并修复了另外两个独立问题（同一次排障中）：

- XIAO 排针焊点虚焊（D5 对 GND 电压异常，补焊解决）
- I2C 400kHz 时钟在补焊总线上不稳（降回默认 100kHz，50Hz 采样带宽足够）

## 解决方案

`firmware/wrist_firmware/sensor_manager.cpp` 改为**裸寄存器驱动**：

- 直接读写 MPU 寄存器（唤醒 0x6B、量程 0x1B/0x1C、滤波 0x1A、数据 0x3B 连读 14 字节）
- 芯片 ID 宽容校验：接受 0x68/0x70/0x71 等（6050/6500/6515 全系）
- 不再依赖 Adafruit_MPU6050 库（该库其他功能仍在，只是本驱动不使用）
- 腰端 MPU 驱动直接复用这份实现

## MPU6500 vs MPU6050 性能影响

| 项 | MPU6050 | MPU6500 | 对本项目影响 |
|----|---------|---------|-------------|
| 加速度计 | 16bit，同类设计 | 基本相同 | 无 |
| 陀螺仪噪声 | 0.005 °/s/√Hz | ≈0.0037 °/s/√Hz | 6500 略优 |
| 量程/分辨率/采样率 | 16bit，±2~16g | 相同配置可用 | 无 |
| 寄存器/数据格式 | 基准 | 兼容 | 无（裸驱动已验证） |

**结论：对跌倒检测（SVM 阈值 + 角速度特征）无实质影响，陀螺噪声甚至略低。**
算法组按原计划标定即可，无需针对型号调整。答辩时可作为"问题定位与解决"的案例讲述。

## 经验

1. 廉价 GY 系模块芯片型号与商品名不符很常见，遇"库不识别"先读 WHO_AM_I
2. I2C 排障顺序：扫描器（地址在不在）→ 读 ID（芯片是什么）→ 时序（降速试）
3. 自焊开发板排针必须逐点测通断，"灯亮"只代表供电脚焊好了
